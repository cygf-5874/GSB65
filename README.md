# colfmt —— 宽字符表格渲染

`colfmt` 是一个纯标准库的 Python 3 小库：把二维文本渲染成**等宽**表格。
列宽按**显示宽度**（终端里占多少列）计算，而不是按码点个数；中文、日文、韩文、
全角标点、emoji、组合记号混排时，整张表每一行的宽度必须严格一致，竖线落在同一列。

```python
from colfmt import render_table

print(render_table(
    [["汉", "a"], ["abc", "汉字"]],
    headers=["名", "值"],
))
```

```
+-----+------+
| 名  | 值   |
+-----+------+
| 汉  | a    |
+-----+------+
| abc | 汉字 |
+-----+------+
```

## API

```python
display_width(text: str) -> int
wrap_text(text: str, width: int) -> list[str]
render_table(rows, headers=None, widths=None, align="left", style="ascii") -> str
```

* `rows`：二维序列，每个元素是一行的单元格文本（`str`）。每行列数必须一致。
* `headers`：`None` 表示没有表头行；否则是长度等于列数的文本序列。表头与该列用同一种对齐。
* `widths`：`None` 表示按内容自动取「每列最大的显示宽度」；给出时是长度等于列数的整数序列，
  单元格超过列宽时被折行。
* `align`：`"left"` / `"right"` / `"center"` 之一，或者长度等于列数的序列（逐列指定）。
* `style`：`"ascii"` / `"light"` / `"none"`。
* 返回值不含结尾换行；`render_table([])` 与 `render_table([], headers=[])` 都返回 `""`。

## 对外契约（11 条）

下面每一条都是对外契约，实现与用例都要守住。**验收以 `check.py` 为准。**
已公开的函数签名不变，可以新增内部函数。

1. **宽度模型**：`display_width(text)` 返回字符串的**显示宽度**——
   East Asian Width 为 `W`（Wide）或 `F`（Fullwidth）的码点记 **2**；
   Unicode 类别为 `Mn` 或 `Me` 的组合记号记 **0**；其余码点（含 `A`/`N`）记 **1**。
   下表是契约固化下来的样例，实现必须逐条命中（`check.py` 用同一张表断言）：

   | 文本 | 显示宽度 | 说明 |
   | --- | --- | --- |
   | `""` | 0 | 空串 |
   | `"a"` / `"abc"` | 1 / 3 | 半角字母 |
   | `" "` / `"  "` | 1 / 2 | 半角空格 |
   | `"#-+"` | 3 | 半角符号 |
   | `"a \| b"` | 5 | 含竖线 |
   | `"汉"` / `"汉字"` | 2 / 4 | `W` |
   | `"Ａ"`（U+FF21） | 2 | `F` |
   | `"。"`（U+3002） | 2 | `W` |
   | `"～"`（U+FF5E） | 2 | `F` |
   | `"한"`（U+D55C） | 2 | `W`（谚文音节） |
   | `"😀"`（U+1F600） | 2 | `W` |
   | `"é"`（U+00E9，单码点） | 1 | `A` 按 1 计 |
   | `"·"`（U+00B7） | 1 | `A` 按 1 计 |
   | `"—"`（U+2014） | 1 | `A` 按 1 计 |
   | `"✓"`（U+2713） | 1 | `N` 按 1 计 |
   | `"e\u0301"`（e + U+0301） | 1 | 1 + 0 |
   | `"\u0301"`（单独的组合尖音符） | 0 | `Mn` |
   | `"漢\u0301"` | 2 | 2 + 0 |
   | `"漢字\u0301"` | 4 | 2 + 2 + 0 |
   | `"e\u0301x"` | 2 | 1 + 0 + 1 |

2. **按显示宽度折行**：`wrap_text(text, width)` 返回折行后的行列表。
   折行是**贪心**的：把文本切成「基字符 + 紧跟其后的组合记号」这样的**不可分割单元**，
   一个单元要么整块留在当前行、要么整块挪到下一行；再加一个单元会超过 `width` 时换行。
   单个单元的显示宽度本身就大于 `width` 时，它单独占一行（这是唯一允许超出列宽的情形）。
   `text` 为空或 `width <= 0` 时返回 `[text]`（原样一行）。
   `wrap_text` 只负责折行，不做任何转义。

3. **对齐**：`left` / `right` / `center` 都按**显示宽度**补空格。
   `center` 时左右留白分别是 `gap // 2` 与 `gap - gap // 2`——**余数差额分配给右侧**。

4. **边框风格三**选一：
   * `ascii`：横 `-`、竖 `|`、顶/中/底行的左右端与交叉都是 `+`；
   * `light`：横 `─`（U+2500）、竖 `│`（U+2502），
     顶行 `┌ ┬ ┐`、中间分隔行 `├ ┼ ┤`、底行 `└ ┴ ┘`；
   * `none`：不画任何边框与横向分隔行，列之间用**单个空格**分隔。
   其中「中间分隔行」指表头与表体之间、以及相邻表体行之间的那一行；相邻两行之间各有一条。
   有边框的风格下，单元格内容两侧各有一个空格；单元格宽度为 `w` 时横线段长度为 `w + 2`。

5. **CJK / ASCII 混排**：同一张表里既有 CJK 行也有 ASCII 行时，所有行（含边框行）
   的显示宽度必须严格相等，即竖线落在同一列。这一条由 1~4 共同保证，
   `check.py` 给出逐字节的期望输出。

6. **边界形状**：空表、只有表头、单行、单列、空字符串单元格都必须有确定输出：
   `render_table([])` 与 `render_table([], headers=[])` 返回 `""`；
   只有表头时输出「顶行 + 表头 + 底行」，没有多余的分隔行。

7. **`\t` 展开**：单元格内的 `\t` 展开为空格，使**相对本单元格起点**的显示宽度
   前进到下一个 8 的倍数；起点宽度已经是 8 的倍数时补足 8 个空格。
   展开后的文本才参与宽度计算与折行。

8. **不允许行尾空格**：返回文本的任何一行都不以空格结尾。
   `none` 风格下每行由各列（按各自宽度补白）以单个空格连接，再去掉行尾空格。

9. **单元格内特殊字符的写死转义**：`render_table` 处理每个单元格的顺序固定为
   ① `|` → `\|`；② 换行符 `\n` → `<br>`；③ 按第 7 条展开 `\t`；④ 按第 2 条折行。
   转义结果参与宽度计算，且不得破坏表格结构（竖线数量与列数一致）。

10. **确定性**：同样的输入、同样的参数，`render_table` 两次调用返回**逐字节相同**的
    字符串。实现不得依赖 `dict` / `set` 的迭代顺序；可以缓存纯函数的计算结果，
    但不得让跨调用的状态影响输出（同输入必须同输出）。

11. **性能**：1000 行 × 12 列的混排表（CJK + ASCII）渲染必须 **< 1 秒**。
    该时限**按本机标定**，跑题机更慢时按比例放宽；`check.py` 的 `perf` 组把上限
    写死在 `PERF_SECONDS = 1.0`。`perf` 组同时校验「整表每行显示宽度一致」，
    避免「快但错」。`bench.py` 是这一条的独立入口。

## 怎么跑

```bash
python3 -m unittest discover -s tests      # 既有用例
python3 check.py -list                     # 列出全部 11 个场景
python3 check.py                           # 跑全部；全过才退 0
python3 check.py --only wrap               # 只跑一组（width / wrap / align / edge / perf）
bash scripts/check.sh                      # 固定验收入口（等价于 python3 check.py）
python3 bench.py                           # 性能入口
```

`check.py`、`scripts/check.sh`、`bench.py` 都是**固定件，不要改**。
`check.py` 的每个场景跑在独立子进程里并带超时看门狗；失败不早退，一次把问题全暴露。

## 版本前提

* Python 3.9 及以上（开发与实测用 3.13），只用标准库（`unicodedata`、`unittest`、
  `time`、`subprocess`）。
* 没有第三方依赖，没有 `requirements.txt`，不需要联网、不需要数据库、不起中间件。
* 判据是确定性的：固定输入、固定参数、固定期望输出；只有 `perf` 组读墙钟。
